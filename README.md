# Stockroom

Stockroom is a public treasury launchpad on Robinhood Chain. It lets a project launch a token with a real, transparent treasury behind it — and turns that treasury into an open balance sheet instead of a wallet address nobody can interpret.

> Launch a token with a public treasury behind it.

## The problem

Most token projects show a price chart, a market cap, and a wallet address. What actually backs the token — how much is held, in what, how it changes over time, whether reserves are healthy — is invisible unless someone manually digs through a block explorer. Treasury management ends up happening behind closed doors: screenshots, unexplained transfers, and trust-me updates.

Stockroom replaces that with a system where the balance sheet is the product.

## What Stockroom actually is

Each project on Stockroom gets:

- **A token** — a standard, fixed-supply ERC-20 with no admin backdoors: no mint function beyond the initial supply, no pausability, no blacklist, no upgrade path. What you see at launch is what exists forever.
- **A treasury** — a dedicated onchain address holding USDG (a USD-pegged stablecoin) and approved Robinhood Stock Tokens (tokenized exposure to real equities, settled onchain). The treasury is never custodied by Stockroom itself; it's controlled by the project's own authorized wallet.
- **A public balance sheet** — total treasury value, reserve ratio, asset allocation, NAV history, and a full activity ledger, all reading directly from onchain state and a synced index of it. Anyone can view this without connecting a wallet.
- **A treasury policy** — a fixed, versioned set of rules for that project: minimum reserve percentage, maximum allocation to any single asset, maximum combined exposure to volatile/crypto assets, and a maximum size for any single trade. Policy is visible publicly, the same way the balance sheet is.
- **A Treasury Agent** — an automated analyst that continuously reads the treasury's real, computed data (holdings, reserve ratio versus policy target, concentration risk, recent activity, cash flow) and produces a plain-language report: is the treasury healthy, what's changed, and what action — if any — it would recommend (build reserves, buy an approved asset, trim an overweight position, or hold).
- **An operator console** — where an authorized human reviews whatever the Treasury Agent proposed, pulls a live execution quote, and decides whether to approve, edit, or reject it.

## The core loop

```
Capital enters the treasury (seed, revenue, deposits)
        ↓
The app reads the treasury wallet and prices every position
        ↓
The Treasury Agent analyses the data and proposes an action
        ↓
A deterministic policy engine checks that proposal against fixed rules
        ↓
An authorized operator reviews the (possibly reduced or rejected) proposal
        ↓
The operator requests a live trade quote and signs the transaction themselves
        ↓
The trade settles onchain and the public balance sheet updates
```

Two things about this loop are non-negotiable by design, not just by convention:

1. **The Treasury Agent never holds a key, signs a transaction, or executes anything.** It receives pre-computed numbers — it doesn't calculate balances itself, and it can't invent a holding or a contract address that isn't already verified. Its only output is a structured, validated report and a proposed action.
2. **Every proposal is independently checked by policy before a human ever sees it**, using the same fixed rules every time — minimum reserves, maximum single-asset exposure, an explicit allowlist of approved assets, and a maximum trade size relative to the treasury's total value. The proposal cannot mark itself compliant. If it breaks a rule, it gets reduced or rejected outright, and that check runs again immediately before execution, not just once.

Execution itself always requires a real signature from an authorized wallet. Stockroom's backend never stores or has access to a private key.

## Where the treasury's money comes from

- **Seed capital** — the team funds the treasury at launch, establishing the first real balance sheet.
- **Protocol/product revenue** — activity generated by the project (trading, fees, subscriptions, partner revenue) can be routed into the treasury automatically, rather than disappearing into a separate operating wallet.
- **Manual deposits** — any wallet can send supported assets to a treasury address; the app detects and displays these automatically, and an operator can label what they represent (seed, revenue, grant, refund, etc.) without ever being able to alter the underlying onchain amount.

Over time this is meant to compound: revenue becomes reserve, reserve backs the token, and the token's credibility is a direct function of a balance sheet anyone can verify rather than a claim anyone has to take on faith.

## Pricing and valuation

Every asset position is priced through two clearly separated layers:

- **Onchain, authoritative pricing** — used for anything that gates a real decision: policy checks, maximum trade size, whether a proposal is even valid. This layer will not present a trade as actionable using data it considers stale.
- **Display metadata** — logos, underlying bid/ask, asset status — used only to make the interface readable, never to authorize a transaction.

Stock Tokens also carry a corporate-action multiplier so that dividends and splits are reflected correctly in valuation without the raw onchain balance itself needing to change.

## Multi-project structure

Stockroom isn't a single treasury dashboard — it's a launchpad. Anyone can launch a project through a guided flow (project details, token configuration, treasury configuration, treasury policy, Treasury Agent setup, review) and immediately get:

- a public project page
- token and treasury detail views
- a policy page
- a Treasury Agent report feed
- a filterable activity ledger
- a private management workspace and operator console

Projects appear in a public registry (Explore) where they can be searched and sorted by treasury size, reserve health, recent activity, and more — the beginnings of a financial registry for projects built on Robinhood Chain, not just a single flagship dashboard.

## Design principles

- **Transparency by default.** Every number displayed publicly has a defined, traceable source — either a direct chain read or a documented calculation on top of one.
- **Separation of concerns.** Analysis, policy, and execution are three distinct layers with three distinct levels of authority. None of them can substitute for another.
- **No custody, ever.** The application reads wallets; it does not hold keys, request seed phrases, or sign on anyone's behalf, at any layer, under any circumstance.
- **Deterministic where it matters.** Anything that decides whether money moves — reserve checks, exposure limits, trade sizing — runs on fixed, auditable rules, not on a model's judgment call.
- **Real assets, real chain.** Treasuries hold real onchain assets on Robinhood Chain: USDG and Robinhood Stock Tokens, which provide economic exposure to underlying equities. Project tokens are not represented as legal ownership of the treasury or as equity in the underlying companies.

## Status

Stockroom is live. The public dashboard, treasury indexing, Treasury Agent reporting, and policy engine are running against real chain data. Trade execution is gated behind a separate rollout flag from the rest of the platform, so the read/analysis layer can be trusted and iterated on independently of when live trading is fully opened up.
